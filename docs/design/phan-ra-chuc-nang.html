1 Tổng quan hệ thống

PhoneStore là hệ thống bán lẻ trực tuyến chuyên điện thoại, máy tính bảng và phụ kiện. Hệ thống cho phép khách hàng lướt danh mục, thêm vào giỏ, đặt hàng thanh toán COD theo dõi đơn và nhân viên quản trị sản phẩm, tồn kho, vận chuyển.

Phạm vi hệ thống

  • Bán lẻ trực tuyến 1 kênh (web API)
  • 5 module nghiệp vụ độc lập
  • Thanh toán COD — chuyển khoản online nằm ngoài phạm vi
  • Quản lý tồn kho và vận chuyển nội bộ

Đối tượng sử dụng

  • Khách hàng — mua sắm, theo dõi đơn
  • Nhân viên — xác nhận đơn, giao hàng, thu COD
  • Quản trị viên — quản lý danh mục, sản phẩm, nhân viên

Kiến trúc

  • Modular Monolith + Clean Architecture
  • .NET 10 · ASP.NET Core Web API
  • PostgreSQL 16 — 5 schema độc lập
  • MediatR (In-memory Event Bus) liên module

5 Đặc tả Use Case chi tiết

Đặc tả dạng lời cho 5 use case trụ cột của hệ thống, mỗi use case gồm: tác nhân, tiền điều kiện, luồng chính, luồng thay thế, điều kiện sau.

UC-01 Thêm sản phẩm vào giỏ hàng

Tác nhânKhách hàng (CUSTOMER)
Tiền điều kiệnĐã đăng nhập; sản phẩm tồn tại và đang bán
Điều kiện sauGiỏ ACTIVE chứa thêm 1 mục hoặc cộng dồn vào mục cũ

Luồng chính

  1. Khách chọn phiên bản (màu, dung lượng) và số lượng
  2. Hệ thống tìm hoặc tạo giỏ ACTIVE của khách
  3. Hệ thống gọi IProductPricingContract lấy giá/tên/SKU từ Catalog
  4. Không tìm thấy → trả 404 PRODUCT_VARIANT_NOT_FOUND
  5. Nếu sản phẩm đã có trong giỏ → cộng dồn số lượng
  6. Kiểm tra giới hạn: ≤10 đơn vị/sản phẩm, ≤50 sản phẩm khác nhau
  7. Vượt giới hạn → 400 VALIDATION_ERROR
  8. Lưu và trả về giỏ hàng đầy đủ

Luồng thay thế

  • Chưa đăng nhập → 401 UNAUTHORIZED
  • Giỏ đã CONVERTED/ABANDONED → tạo giỏ ACTIVE mới

UC-02 Checkout COD — tạo đơn hàng

Tác nhânKhách hàng (CUSTOMER)
Tiền điều kiệnĐã đăng nhập; giỏ ACTIVE không rỗng
Điều kiện sauĐơn PENDING được tạo; giỏ chuyển CONVERTED

Luồng chính

  1. Khách nhập tên, SĐT, địa chỉ nhận hàng, ghi chú (tuỳ chọn)
  2. Hệ thống đọc giỏ ACTIVE qua ICartContract
  3. Giỏ rỗng → 400 "Giỏ hàng đang trống, không thể checkout."
  4. Lấy lại giá từ Catalog cho từng mục (không dùng giá trong giỏ)
  5. Sản phẩm không còn bán → 400 "Sản phẩm X không còn được bán."
  6. Sinh mã đơn ORD-{yyyyMMdd}-{6 hex}, thử tối đa 5 lần nếu trùng
  7. Mở TransactionScope
  8. Tạo Order (PENDING, COD) + OrderItem[] + lịch sử trạng thái đầu
  9. Tính: Subtotal → ShippingFee (0 nếu ≥10tr, 30.000 nếu không) → Total
  10. Đánh dấu giỏ CONVERTED
  11. Commit → trả 201 Created

Luồng thay thế

  • Bất kỳ bước nào lỗi → scope không Complete → rollback toàn bộ, giỏ vẫn ACTIVE

UC-03 Xem danh sách đơn hàng

Tác nhânKhách hàng (CUSTOMER)

Luồng chính

  1. Khách gọi GET /api/v1/orders/{orderId}
  2. Không tìm thấy → 404 ORDER_NOT_FOUND
  3. Đơn thuộc khách khác → 403 FORBIDDEN

Quyết định thiết kế: trả 403 thay vì 404 cho đơn của người khác. Đã xác thực thành công nhưng không đủ quyền — 404 sẽ gây nhầm lẫn "đơn không tồn tại" và che mất nguyên nhân thật.

UC-05 Hủy đơn hàng

Tác nhânKhách hàng (CUSTOMER)
Tiền điều kiệnĐã đăng nhập; đơn ở trạng thái PENDING hoặc CONFIRMED
Điều kiện sauĐơn CANCELLED; tồn kho được hoàn lại

Luồng chính

  1. Khách gửi lý do hủy
  2. Kiểm tra quyền sở hữu → không phải chủ đơn thì 403
  3. Kiểm tra trạng thái: chỉ PENDING/CONFIRMED mới hủy được
  4. Sai trạng thái → 409 INVALID_ORDER_STATUS
  5. Set CANCELLED + CancelReason + CancelledAt, ghi vào lịch sử trạng thái
  6. Phát domain event OrderCancelled (kèm danh sách item)
  7. SaveChanges → dispatch event sau commit
  8. Event Bus → OrderCancelledHandler → Inventory hoàn tồn
  9. Trả về chi tiết đơn đã cập nhật

Luồng thay thế

  • Hủy lần 2 → 409, tồn kho không bị hoàn 2 lần (đã có test khẳng định)
  • Đơn đã giao (SHIPPING/DELIVERED) → 409, không thể hủy

8 Yêu cầu phi chức năng — chi tiết kỹ thuật

Mỗi NFR được gắn với cơ chế cụ thể đã hiện thực trong code, để có thể kiểm chứng thay vì chỉ khẳng định.

Kiến trúc & phân tách

  • Modular Monolith — 5 module, 5 DbContext, 5 schema
  • Clean Architecture — Domain → Application → Infrastructure
  • Domain thuần túy: không EF Core, không HTTP status code
  • Chỉ aggregate root được phát domain event
  • 7 architecture test chặn rò rỉ tham chiếu

Giao tiếp liên module

  • ICartContract — đọc giỏ, đánh dấu CONVERTED
  • IInventoryContract — đặt giữ / hoàn tồn kho
  • IProductPricingContract — lấy giá server-side
  • IEventBus + MediatR — OrderCancelled
  • Contract nằm ở BuildingBlocks/Contracts/

Chất lượng & kiểm thử

  • 35 unit test — domain + application service
  • 7 architecture test — ranh giới module
  • 126 integration test — HTTP thật qua WebApplicationFactory
  • DB test random phonestore_test_<guid>, tự xoá
  • Tắt parallelization do override biến môi trường toàn cục

Vận hành

  • docker-compose: PostgreSQL 16 (5433) + MinIO (9000/9001)
  • EF Core migration riêng cho từng schema
  • GitHub Actions: service postgres + 3 bước build/test
  • Swagger UI ở root, OpenAPI JSON kèm XML doc
  • Seeder idempotent cho môi trường Development
